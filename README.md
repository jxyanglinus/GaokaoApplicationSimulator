# GaokaoApplicationSimulator · 高考志愿投档模拟器

用 C++17 模拟「3+1+2」新高考的**平行志愿投档**。纯控制台、无 Qt 依赖的 qmake 工程。

> **范围**：本程序只做投档——投档单位是「院校专业组」，输出「谁被投到哪个专业组」，
> 以及每个专业组的投档线和末位投档者的各科成绩。
> 档案进校后的专业录取、是否服从调剂、退档等由高校负责，**不在本程序范围内**。

## 构建与运行

- 工具链：C++17、qmake（`CONFIG -= qt`，不链接 Qt 库），在 Qt 6.5.3 MinGW 64-bit 下编译运行通过。
- 命令行构建：

  ```bat
  qmake GaokaoApplicationSimulator.pro
  mingw32-make -j
  debug\GaokaoApplicationSimulator.exe
  ```

- 源码为 UTF-8（含中文注释）；若改用 MSVC，需额外加 `/utf-8`。
- 运行 exe 需要 MinGW 运行库在 PATH 中（如 `C:\Qt\Tools\mingw1120_64\bin`）；在 Qt Creator 里运行则无需处理。
- 用法：

  ```bat
  GaokaoApplicationSimulator.exe [院校文件] [考生文件] [输出目录]
  :: 默认读取 data/universities.csv、data/students.csv，结果写入 output/
  ```

## 领域模型

```
AcademicScore ──┐
                ├── Student ──1..45── Preference ──1── University ──*── MajorGroup ──*── Major
  成绩/排序规则 ┘        （志愿表）      （院校专业组志愿）      （院校）      （专业组）      （专业）

AdmissionEngine：输入考生 + 院校 → 输出每名考生的投档去向 + 每个专业组的投档线
投档引擎只使用：考生成绩与位次、志愿顺序、专业组的选科/语种要求、组计划与已投档人数。
```

- **投档单位是「院校专业组」**：`Preference` 记录院校 + 专业组；组内专业列表只作为志愿表数据保留，不参与投档。
- **计划**：`Major` 记录计划数，`MajorGroup::getQuota()` 由组内专业求和得到。
- **状态**：`MajorGroup::submittedCnt` 是唯一运行状态（已投档/进档人数），投档容量由它判断。

## 投档规则

1. **分数优先**：所有考生按 7 级同分规则排出位次，位次靠前的先检索志愿；
2. 每人依次检索自己的 45 个院校专业组志愿；
3. 每个志愿先做组层面的资格校验：首选科目、再选科目、外语语种；
4. 再看专业组容量：已投档人数 < 组计划 → 投档，本轮后续志愿不再检索；
5. 组计划已满 → 跳过，继续下一个志愿；45 个志愿都投不出去即**滑档**，进入征集志愿。

**投档比例固定 1:1**，进档人数不会超过计划数，不存在超额投档；位次相同的情况在这套 7 级规则下未出现过。

**投档线** = 该专业组最后一名（位次最低）投档考生的总分，同时输出该考生的各科成绩。
组未投满时没有“投档线”概念，只给出当前最低投档分。

## 已实现的规则

1. **同分排序**（`Student::operator<`）：总分 → 语数之和 → 语数单科最高 → 外语 → 首选科目 → 再选最高 → 再选次高；配合 `std::sort` 得到从高到低。
2. **选科要求**（`MajorGroup::isSecondaryAccepted`）：要求掩码为 0 表示不限；否则考生再选掩码需包含全部要求科目。
3. **语种要求**（`MajorGroup::isLanguageAccepted`）：`permittedLang` 为空表示不限。
4. **容量上限**：45 个院校专业组志愿、每组 6 个专业，超限返回 `OverLimit`。
5. **投档引擎**（`AdmissionEngine::run`）：排序、逐志愿检索、1:1 投档，并记录 `SlotStatus`（投档成功 / 专业组满额 / 院校或组不存在 / 首选不符 / 再选不符 / 语种不符）。

## 投档引擎接口

```cpp
AdmissionReport AdmissionEngine::run(const std::vector<Student> &students,
                                     std::vector<University> &universities);
```

`AdmissionReport` 包含两部分：

- `students`：每名考生的 `StudentSubmission`，下标与传入的 `students` 一致；
  - `submitted` / `toUniversityId` / `toGroupId` / `toPreferenceIndex`：投档去向；
  - `slotStatuses`：按志愿顺序记录检索结果，命中即停。
- `groups`：每个专业组的 `GroupCutoff`；
  - `quota` / `submittedCnt`：计划数与进档人数；
  - `hasCutoff` / `lastStudentId` / `lastTotal`：是否有投档、末位投档者、投档线。

## 数据文件

两个输入文件均为 UTF-8，允许 `#` 注释行、空行和 BOM；字段按英文逗号分隔，字段内不能含英文逗号。

### data/universities.csv

每行一个专业；同一专业组的院校号、组号、要求会在多行重复：

| 列 | 含义 |
| --- | --- |
| 1 | 院校号（整数） |
| 2 | 院校名称 |
| 3 | 专业组号（院校内唯一） |
| 4 | 首选科目：物理 / 历史 |
| 5 | 再选要求：不限 / 化学 / 化学+生物（用 `+` 连接） |
| 6 | 专业号（整数） |
| 7 | 专业名称 |
| 8 | 计划数（整数） |
| 9 | 语种要求：不限 / 英语 / 英语;日语（用 `;` 连接） |

### data/students.csv

| 列 | 含义 |
| --- | --- |
| 1 | 考生号（整数） |
| 2 | 姓名 |
| 3 | 语文 |
| 4 | 数学 |
| 5 | 外语语种：英语 / 日语 / 俄语 / 德语 / 法语 / 西班牙语 |
| 6 | 外语分 |
| 7 | 首选科目：物理 / 历史 |
| 8 | 首选科目分 |
| 9–12 | 化学、地理、政治、生物（按此顺序，填 0 表示未选考） |
| 13 | 志愿：`院校号:专业组;院校号:专业组` |

### 输出 output/

- `student_results.csv`：`考生号,姓名,总分,是否投档,院校号,院校名称,专业组`
- `group_cutoffs.csv`：`院校号,院校名称,专业组,计划数,投档人数,是否投满,投档线,末位考生号,末位姓名,语文,数学,外语语种,外语,首选科目,首选,再选一,再选一分数,再选二,再选二分数`

两个文件都带 UTF-8 BOM，可直接用 Excel 打开。

## 已知问题与建议

- `AddGroupResult` 与 `AddMajorResult` 是两个内容相同的枚举，可合并为一个 `AddResult`。
- `addGroupById` / `addMajorById` 目前是“假成功”：只做了数量校验，没有真正写入条目。接入目录后应改为先查再插。
- `AcademicScore` 使用 `secScore[i] > 0` 判断是否选考，依赖「0 分不作为有效成绩」这一前提；再选科目赋分起点为 30 分，目前成立，但建议改成显式的选考标记。
- 同分排序没有额外兜底键：若测试数据造出 7 级完全相同的两名考生，`std::sort` 不稳定会让顺序取决于输入，必要时可改用 `std::stable_sort`。
- CSV 不处理引号与转义：姓名、专业名、院校名中不能出现英文逗号。
- 同一专业组的多行如果首选/再选/语种填写不一致，装载时不会报错，以第一行为准。
- 院校、专业组的查找是线性遍历，数据量大时需要改成哈希表。
- 建议把代码移到 `src/` + `include/`，把引擎从 header-only 拆成 `.h/.cpp`。
